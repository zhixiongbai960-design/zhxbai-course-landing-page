# 设计与精简规范

## 参考图如何用

长海报先拆成内容模块和阅读顺序，区分主张、课程、证明、政策与报名。低清图看不清的字不要猜。复用信息组织思路，不描摹他人的身份、 logo 或宣传承诺。

用户已提供现有公众号、信息卡风格时，以其视觉系统为准；不要因参考海报颜色不同而重做品牌。

## 信息结构

| 模块 | 用户要得到的答案 | 限制重复 |
|---|---|---|
| 首屏 | 什么课、为什么值得看、何时何地、价格摘要 | 不展开全部成果和服务 |
| 适合谁 | 两三类角色各得什么、基础、不适合谁 | 不再在FAQ重新列目标用户 |
| 当场成果 | 项目方法、能力、可带走产品分别是什么 | 少用无法核验的能力保证 |
| 后续支持 | 讲义、模板、Skill、答疑、复训怎样继续使用 | 不与成果卡反复解释同一价值 |
| 课程安排 | 每时段做什么、形成什么结果 | 不同时堆长说明、同义标签和结果 |
| 讲师 | 相关经验与实际做过的事情 | 不把同一履历写三次 |
| 报名 | 完整日期地点、规模、收费边界和真实入口 | 与首屏允许必要摘要重复 |

FAQ仅用于尚未回答的重要问题；没有新信息就删整个模块，不为了长页完整感而补问答。

## 默认蓝白风格

用户没有另指定风格时使用本次沉淀的轻量视觉：

- 主蓝 `#0052D9`，深色标题 `#111C30`，辅助文字 `#607086`。
- 白底，浅蓝 `#EEF4FF` 容器，细线 `#DCE5F1` 分区。
- 大标题与数字抓注意力，结构图、成果卡和时间轴帮助扫描。
- 桌面内容宽约1120px；移动端单列，左右留白约20—24px。
- 核心报名信息在手机上早出现，不让大插图将日期和价格推到长滚动之后。
- 默认用HTML/CSS表达流程和架构，不为了装饰生成大图片；照片与二维码必须使用用户提供的真实资源。
- 系统中文字体优先；一页静态需求不默认引入框架、第三方字体、CDN或分析追踪。

模板的结构和尺寸均可调整，不要求复制原样。需要报价、登录或收款功能时，先明确新的产品范围。

## 文案精简

逐段检查「新增了什么信息」。没有增量就删除。

- 把「建立工程化思维的能力，帮助形成可持续工程化实践」改为具体动作，如拆输入、处理、输出、异常。
- 把成果写成名称＋用途，少堆「完整、系统、全流程、全面」等近义词。
- 用一句话说明时段内容，用一句话写阶段产出。若两句仍同义，合并。
- 一段超过约80个中文字符可优先复查；这是编辑提示，不是强制字数上限。
- 允许首屏与报名区重复日期、价格等关键摘要，其他细节默认只展开一次。
- 专业度用可验证的经历和交付结果建立，避免「只有我能教」「保证接到订单」等无根据的排他或收益承诺。
- 价格、人群限制、费用边界、服务条件不能为了缩短而丢失。
- 不把「一人公司交付经验」写成只给建议、由别人负责交付；尊重真实职业经历。

精简比例不是目标。本次改稿删除约四成可见字数只是一次经验，其他页面以信息完整与阅读清晰为准。

## 检查

1. 是否所有业务事实都来自当前课程而非参考图或模板？
2. 是否明确当前价格、原价、单人或团体、费用范围？促销条件有无臆造？
3. 两类角色的区别是否清楚？基础和不适合者是否表达适度？
4. 可带走的产品与实操载体是否区分？支持内容是否超出已确认范围？
5. 在1280、768、390、320px宽度检查文字、图示、价格和报名入口。
6. 锚点唯一且目标存在，浏览器无脚本错误，图片加载正常。
7. 实际看截图，确认不截字、不遮住标题、间距合理。
8. 若只做本地文件，不宣称页面已上线；外部部署与上传另行执行。
